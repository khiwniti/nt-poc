# Production Environment Checklist

Use this checklist to ensure all services are properly configured for production deployment on Railway.

## Database Configuration

- [ ] PostgreSQL service created on Railway
- [ ] TimescaleDB extension enabled: `CREATE EXTENSION IF NOT EXISTS timescaledb;`
- [ ] Database credentials noted (auto-generated by Railway)
- [ ] Connection tested successfully

## Backend Service

### Environment Variables
- [ ] `NODE_ENV=production`
- [ ] `PORT=3000`
- [ ] `DB_HOST=${{Postgres.PGHOST}}`
- [ ] `DB_PORT=${{Postgres.PGPORT}}`
- [ ] `DB_NAME=${{Postgres.PGDATABASE}}`
- [ ] `DB_USER=${{Postgres.PGUSER}}`
- [ ] `DB_PASSWORD=${{Postgres.PGPASSWORD}}`
- [ ] `DB_SSL=true`
- [ ] `JWT_SECRET=<256-bit-secret>` ⚠️  **Generate strong secret!**
- [ ] `JWT_EXPIRY=24h`
- [ ] `MLOPS_SERVICE_URL=https://${{MLOps.RAILWAY_PRIVATE_DOMAIN}}`
- [ ] `SIMULATOR_URL=https://${{Simulator.RAILWAY_PRIVATE_DOMAIN}}`
- [ ] `SENSOR_INGESTION_ENABLED=true`
- [ ] `SENSOR_INGESTION_INTERVAL=10000`
- [ ] `PREDICTION_JOB_INTERVAL_MINUTES=60`
- [ ] `ESCALATION_JOB_INTERVAL_MINUTES=5`
- [ ] `LOG_LEVEL=info`

### Optional Environment Variables
- [ ] `SENDGRID_API_KEY` (for email notifications)
- [ ] `EMAIL_FROM` (sender email)
- [ ] `DASHBOARD_BASE_URL` (frontend URL)
- [ ] `MAPBOX_ACCESS_TOKEN` (for maps)
- [ ] `GOOGLE_MAPS_API_KEY` (for geocoding)
- [ ] `WEATHER_API_KEY` (for weather data)
- [ ] `SENTRY_DSN` (for error tracking)
- [ ] `METRICS_AUTH_TOKEN` (for metrics endpoint protection)

### Deployment
- [ ] Service created with root directory: `services/backend`
- [ ] `railway.json` detected (DOCKERFILE builder)
- [ ] Build successful
- [ ] Migrations ran automatically (check logs for ✅ message)
- [ ] Health check passing: `/api/v1/health`
- [ ] Service is publicly accessible

## Service Integration Testing

### Health Checks
- [ ] Backend: `curl https://backend.railway.app/api/v1/health`
- [ ] MLOps: `curl https://mlops.railway.app/health`
- [ ] Simulator: `curl https://simulator.railway.app/api/health`
- [ ] Frontend: Browser loads successfully

### Data Flow
- [ ] Simulator generates sensor readings
- [ ] Backend ingests sensor data (check logs: `sensor_ingestion_run_completed`)
- [ ] Backend triggers ML predictions (check logs: `scheduled_prediction_job_run_completed`)
- [ ] Frontend displays real-time sensor data
- [ ] Predictions visible in frontend dashboard

### Chatbot RAG
- [ ] Chatbot widget loads
- [ ] Can send messages
- [ ] Receives AI responses
- [ ] Query: "What's the current status?" returns system summary
- [ ] Query: "Show me critical alerts" returns alert data from database
- [ ] Query: "What's the battery health?" returns SoH information

### Backend → MLOps Communication
- [ ] Backend can reach MLOps service
- [ ] RUL predictions succeed
- [ ] No circuit breaker errors in logs
- [ ] Check backend logs for `mlops_predict_rul_success`

### Backend → Simulator Communication
- [ ] Backend can reach Simulator service
- [ ] Sensor readings ingested successfully
- [ ] Check backend logs for `sensor_ingestion_run_completed`

## Database Verification

- [ ] Migrations table exists and has entries
- [ ] Facilities table has data
- [ ] Battery systems table has data
- [ ] Sensor readings table receiving data (TimescaleDB hypertable)
- [ ] RUL predictions table receiving predictions
- [ ] Alerts table working

Query to check:
```sql
SELECT COUNT(*) FROM sensor_readings;
SELECT COUNT(*) FROM rul_predictions;
SELECT COUNT(*) FROM alerts;
```

## Security

- [ ] All secrets stored in Railway environment variables (not in code)
- [ ] JWT secret is strong and unique (256-bit minimum)
- [ ] Database SSL enabled
- [ ] CORS properly configured
- [ ] API keys rotated regularly
- [ ] No secrets in git repository
- [ ] `.env` files in `.gitignore`

## Monitoring & Logging

- [ ] Backend logs visible in Railway
- [ ] MLOps logs visible in Railway
- [ ] Simulator logs visible in Railway
- [ ] Frontend logs/errors tracked (browser console)
- [ ] Sentry configured (optional but recommended)
- [ ] Prometheus metrics accessible at `/metrics` (with auth token)

## Performance

- [ ] Health checks responding < 100ms
- [ ] API requests responding < 500ms
- [ ] Sensor ingestion running every 10 seconds
- [ ] RUL predictions running every 60 minutes
- [ ] Frontend loads < 3 seconds
- [ ] No memory leaks (monitor Railway metrics)

## Backup & Recovery

- [ ] Railway automatic backups enabled for PostgreSQL
- [ ] Backup schedule configured (daily at 2 AM UTC)
- [ ] Recovery procedure documented
- [ ] Test restore performed

## API Keys to Acquire

1. **Google Gemini API Key** ⚠️  **Critical for chatbot**
   - Go to: https://ai.google.dev/
   - Create API key
   - Add to frontend: `VITE_GEMINI_API_KEY`

2. **JWT Secret** ⚠️  **Critical for authentication**
   - Generate: `openssl rand -base64 32`
   - Add to backend: `JWT_SECRET`

3. **SendGrid API Key** (Optional)
   - For email notifications
   - https://sendgrid.com/

4. **MapBox Token** (Optional)
   - For map features
   - https://www.mapbox.com/

5. **OpenWeather API Key** (Optional)
   - For weather data
   - https://openweathermap.org/api

6. **Sentry DSN** (Optional)
   - For error tracking
   - https://sentry.io/

## Post-Deployment Verification

- [ ] No critical errors in logs

### Short-term (5-30 minutes)

### Long-term (1-24 hours)
- [ ] RUL predictions generated (after 60 minutes)
- [ ] Alert escalation working (if configured)
- [ ] No memory leaks or crashes
- [ ] Database backups running

## Troubleshooting Quick Reference

| Issue | Check | Solution |
|-------|-------|----------|
| Migrations fail | Startup logs | Verify DB connection, run manually |
| Service can't connect | Environment variables | Verify Railway domain references |
| Chatbot not working | GEMINI_API_KEY | Add key to frontend env vars |
| No sensor data | SIMULATOR_URL | Check URL and simulator health |
| MLOps errors | Circuit breaker logs | Check MLOps service health |
| Frontend blank | Browser console | Check API_BASE_URL and CORS |
