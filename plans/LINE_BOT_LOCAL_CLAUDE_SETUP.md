# LINE Bot - Local Claude Sonnet 4.5 Configuration

**Last Updated**: 2026-01-14  
**Purpose**: Configure LINE Bot to use Claude Sonnet 4.5 running locally on port 4141

## Overview

This guide configures the LINE Bot to use a local Claude Sonnet 4.5 instance running on `localhost:4141` instead of OpenAI. This setup assumes you have a local server (like LiteLLM, vLLM, or similar) that provides an OpenAI-compatible API endpoint serving Claude models.

## Prerequisites

### 1. Local Claude Server Running

Verify your local Claude server is running:

```bash
# Check if port 4141 is listening
lsof -i :4141

# Or try connecting
curl http://localhost:4141/v1/models
```

**Expected response**: JSON with available models

### 2. Identify Model Name

Your local server might use different model names. Common formats:
- `claude-sonnet-4.5`
- `anthropic.claude-sonnet-4.5`
- `claude-3-sonnet`
- Or custom alias configured in your server

Check available models:

```bash
curl http://localhost:4141/v1/models | jq '.data[].id'
```

## Configuration Steps

### Step 1: Update `.env` File

Edit [`services/line-bot/.env`](../services/line-bot/.env):

```bash
# ============================================================================
# AI Provider Configuration - Local Claude Sonnet 4.5
# ============================================================================

AI_PROVIDER=custom
AI_BASE_URL=http://localhost:4141/v1
AI_MODEL=claude-sonnet-4.5
AI_API_KEY=not-required

# Optional: Increase timeout for Claude (can be slower than GPT)
AI_REQUEST_TIMEOUT=60000

# Optional: Retry configuration
AI_MAX_RETRIES=3

# Keep existing LINE Bot config
LINE_CHANNEL_SECRET=your_channel_secret
LINE_CHANNEL_ACCESS_TOKEN=your_channel_access_token
API_SECRET_KEY=your_api_secret_key
PORT=3002
```

### Step 2: Verify Configuration

Check that configuration is correct:

```bash
# View current .env (without sensitive data)
grep "^AI_" services/line-bot/.env | grep -v "API_KEY"
```

**Expected output**:
```
AI_PROVIDER=custom
AI_BASE_URL=http://localhost:4141/v1
AI_MODEL=claude-sonnet-4.5
AI_REQUEST_TIMEOUT=60000
AI_MAX_RETRIES=3
```

### Step 3: Start LINE Bot Service

```bash
cd services/line-bot
npm run dev
```

**Look for in logs**:
```
AI Provider initialized {
  provider: 'custom',
  model: 'claude-sonnet-4.5',
  baseURL: 'http://localhost:4141/v1'
}
```

### Step 4: Test Health Endpoint

```bash
curl http://localhost:3002/health | jq '.'
```

**Expected response**:
```json
{
  "status": "ok",
  "service": "line-bot",
  "timestamp": "2026-01-14T02:36:46.759Z",
  "version": "1.0.0",
  "ai": {
    "provider": "custom",
    "model": "claude-sonnet-4.5",
    "healthy": true
  }
}
```

If `ai.healthy` is `false`, check the error message and verify your local Claude server.

### Step 5: Test AI Response

```bash
# Test with the notify endpoint
curl -X POST http://localhost:3002/notify \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_API_SECRET_KEY" \
  -d '{"message": "Hello, can you help me with battery monitoring?"}'
```

**Expected**: Success response from LINE Bot (it will attempt to broadcast to LINE followers)

### Step 6: Test with LINE App

1. Open LINE mobile app
2. Send message to your bot: "What is the battery status?"
3. Bot should respond using Claude Sonnet 4.5

**Expected behavior**:
- Response generated by Claude (may have different style than GPT)
- Response time: 1-5s depending on your hardware
- Clear, concise answers suitable for chat

## Troubleshooting

### Issue: "Cannot connect to AI service"

**Check 1**: Verify local Claude server is running
```bash
lsof -i :4141
curl http://localhost:4141/v1/models
```

**Fix**: Start your local Claude server on port 4141

---

### Issue: "Model not found"

**Check 1**: List available models
```bash
curl http://localhost:4141/v1/models | jq '.data[].id'
```

**Fix**: Update `AI_MODEL` in `.env` to match an available model name

Example corrections:
```bash
# If your server uses:
AI_MODEL=anthropic.claude-sonnet-4.5
# or
AI_MODEL=claude-3-sonnet
# or
AI_MODEL=claude-sonnet
```

---

### Issue: "Response timeout"

**Cause**: Claude models can be slower than GPT, especially on CPU

**Fix 1**: Increase timeout
```bash
AI_REQUEST_TIMEOUT=90000  # 90 seconds
```

**Fix 2**: Check your local server's performance
```bash
# Time a request
time curl -X POST http://localhost:4141/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4.5",
    "messages": [{"role": "user", "content": "Hello"}],
    "max_tokens": 100
  }'
```

---

### Issue: "AI health check failed"

**Debug steps**:

### Request Parameters

Adjust Claude-specific parameters in the implementation:

```typescript
// In aiResponse.ts (requires Code mode to edit)
const completion = await this.client.chat.completions.create({
    messages: [...],
    model: this.config.model,
    temperature: 0.7,        // Claude works well at 0.7
    max_tokens: 500,         // Suitable for LINE messages
    top_p: 0.9,             // Claude default
});
```

## Migration Back to Cloud (If Needed)

To switch back to OpenAI or another cloud provider:

```bash
# For OpenAI
AI_PROVIDER=openai
AI_API_KEY=sk-your-key
AI_MODEL=gpt-3.5-turbo
# Remove or comment out AI_BASE_URL

# For OpenRouter (Claude via API)
AI_PROVIDER=openrouter
AI_API_KEY=sk-or-v1-your-key
AI_MODEL=anthropic/claude-3-sonnet
AI_BASE_URL=https://openrouter.ai/api/v1
```

Then restart: `npm run dev`
